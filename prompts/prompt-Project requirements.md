Ты — senior Android-разработчик. Твоя задача: сгенерировать полный, готовый к компиляции проект Android Studio на Kotlin для приложения "piluli" (напоминания о приеме лекарств).

🔧 ТЕХНОЛОГИЧЕСКИЙ СТЕК:
- Язык: Kotlin
- UI: Jetpack Compose (Material 3)
- Архитектура: MVVM + Clean Architecture (упрощенная: presentation / data / domain)
- Локальное хранилище: Room Database
- Фоновые задачи: WorkManager + NotificationManager (для напоминаний)
- DI: Manual (для совместимости с 7B-моделью, без Hilt/Dagger)
- Асинхронность: Kotlin Coroutines + Flow
- Целевой API: minSdk 26, targetSdk 34
- Gradle Kotlin DSL
- Repository pattern


📦 ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ:
- описаны в дополнительном промпте

📝 ТРЕБОВАНИЯ К КОДУ:
- Каждый файл должен содержать подробные комментарии на русском языке, объясняющие логику работы, потоки данных и назначение компонентов.
- Разделение по пакетам: `ui`, `data`, `domain`, `util`, `di` (если применимо).
- Использование `ViewModel` + `StateFlow` для управления UI-состоянием.
- Обработка ошибок (try/catch, fallback UI, корневые исключения логгируются).
- Код должен быть компактным, без избыточных абстракций, чтобы корректно обрабатываться 7B-моделью.

Правила создания:
- Используйте Material3
- При необходимости используйте rememberSaveable
- Минимизируйте количество перекомпоновок
- Поднимайте состояние вверх
- Поддерживайте темную тему
- По возможности избегайте запуска сопрограмм непосредственно внутри компонентов

При внесении изменений в существующий код:
- Сохраняйте текущую архитектуру.
- Используйте существующие шаблоны.
- Не переписывайте несвязанный код.
- Сведите к минимуму критические изменения.
- Всегда проверяйте импорт и зависимости Gradle перед генерацией кода.
- Не используйте экспериментальные API, если это не требуется в явном виде.

Перед генерацией кода:
1. Проанализируйте текущую структуру проекта.
2. Определите существующие архитектурные шаблоны.
3. Следуйте существующим соглашениям об именовании.
4. Кратко опишите планируемые изменения.
5. Генерируй реализацию после однозначного моего подтверждения.

Тестирование:
- Предпочитайте тестируемую архитектуру
- Бизнес-логика должна быть удобна для модульного тестирования

📄 ДОКУМЕНТАЦИЯ:
Создай файл `README.md` в корне проекта, содержащий:
- Краткое описание приложения "piluli".
- Структуру проекта с пояснением назначения каждого пакета/файла.
- Описание логики работы напоминаний (как WorkManager синхронизируется с Room, как генерируются уведомления).
- Инструкцию по сборке и запуску.
- Пошаговую инструкцию по тестированию (ручное тестирование UI, проверка уведомлений, проверка edge cases: удаление препарата, отмена напоминания, перезагрузка устройства).

📤 ФОРМАТ ВЫВОДА:
Выводи проект строго пофайлово в следующем формате:
📁 app/src/main/java/com/example/piluli/
📄 MainActivity.kt
... (полный код файла)

Не пропускай файлы. Если вывод обрезается из-за лимита токенов, напиши "ПРОДОЛЖЕНИЕ СЛЕДУЕТ" и остановись на логичной границе. Я попрошу продолжить.

⚠️ ВАЖНО:
- Не используй устаревшие API (не используй AsyncTask, Handler, XML-верстку).
- Уведомления должны запрашивать `POST_NOTIFICATIONS` permission на API 33+.
- Все строки, названия кнопок и подсказки должны быть на русском языке.
- Добавь `android:exported="true"` в `AndroidManifest.xml` только там, где это необходимо.

Начни генерацию проекта.
