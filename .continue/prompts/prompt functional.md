📦 Требования к приложению Piluli (название на русском языке: Пилюли)

1. Общая концепция:
   Piluli — Android-приложение для управления приёмом лекарств, витаминов и БАДов с функциями:

- расписания;
- напоминаний;
- контроля пропусков;
- отслеживания остатков;
- аналитики приёма;
- поддержки пользовательских курсов лечения.

Приложение должно быть:

- простым;
- быстрым;
- офлайн-доступным;
- удобным для ежедневного использования;
- масштабируемым под будущие AI-функции.

2. Цели приложения
   Основные задачи:

- Не забывать принимать препараты.
- Контролировать регулярность.
- Учитывать остатки лекарств.
- Помогать проходить курсы лечения.
- Давать понятную аналитику.
- Минимизировать количество действий пользователя.

3. Целевая аудитория
   Основная:

- Люди с постоянным приёмом препаратов.
- Пользователи витаминов и БАДов.
- Пациенты с длительными курсами лечения.

Дополнительная:

- Родители.
- Пожилые пользователи.
- Люди после операций/лечения.
- Пользователи спортивного питания.

4. Функциональные требования
   4.1 Управление препаратами
   Пользователь может:

- добавить препарат;
- редактировать;
- архивировать;
- удалить.

Поля препарата

- Название;
- Дозировка;
- Тип:
  - таблетки;
  - капсулы;
  - капли;
  - инъекции;
  - порошок;
  - другое;
- Фото упаковки;
- Комментарий;
- Цвет/иконка.

  4.2 Расписание приёма:
  Поддержка:

- ежедневно;
- по дням недели;
- несколько раз в день;
- циклических схем;
- курсов;
- приёма “по необходимости”.

Параметры:

- Время приёма
- Количество
- Дата начала
- Дата окончания
- Интервал
- Повторяемость

  4.3 Напоминания
  Система уведомлений должна:

- работать офлайн;
- поддерживать точное время;
- повторять уведомления;
- учитывать часовой пояс;
- поддерживать snooze.

Действия из уведомления

- Принял
- Пропустить
- Отложить

  4.4 Учёт приёма
  Фиксация:

- принят;
- пропущен;
- отложен.

Сохранять:

- дату;
- время;
- фактическое отклонение;
- комментарий.

  4.5 Остатки препаратов
  Пользователь указывает:

- начальное количество;
- минимальный остаток.

Приложение:

- автоматически списывает;
- предупреждает о заканчивающемся препарате;
- прогнозирует дату окончания.

  4.6 Аналитика

Отображать:

- процент соблюдения;
- пропуски;
- серии успешного приёма;
- статистику по дням/неделям/месяцам.

Визуализация
календарь;
графики;
streak-система.

4.7 История

Хранение:

- истории приёмов;
- изменений расписания;
- завершённых курсов.

  4.8 Резервное копирование

Поддержка:

- локального экспорта;
- импорта;
- облачной синхронизации (в будущем).

Форматы:

- JSON
- encrypted backup


4.9 Требования к настройкам приложения Piluli
4.9.1. Общие требования
Раздел настроек должен:
-быть простым;
- содержать только полезные параметры;
- не перегружать пользователя;
- поддерживать быстрый доступ к критичным функциям.
Настройки должны храниться локально и применяться без перезапуска приложения.

4.9.2. Разделы настроек
4.9.2.1 Общие:
Язык приложения:
Поддержка:
- русский;
- английский;
- системный язык.

Тема оформления
Режимы:
- светлая;
- тёмная;
- системная.

Формат времени
- 24 часа
- 12 часов

Первый день недели
- понедельник
- воскресенье

4.9.2.2 Уведомления
Основные настройки:
Глобальное включение уведомлений:
- Пользователь может полностью отключить напоминания.

Звук уведомлений
Настройки:
- системный;
- кастомный звук;
- без звука.

Вибрация:
- включить/выключить;
- интенсивность (опционально).

Snooze по умолчанию
Варианты:
- 5 минут
- 10 минут
- 15 минут
- 30 минут
- пользовательское значение

Количество повторов уведомления:
- Настраиваемое количество повторений при отсутствии ответа пользователя.
- по умолчанию 3 повтора

4.9.2.3 Настройки приёма
Автоматическая отметка пропуска:
Если пользователь не ответил на уведомление:
- никогда;
- через X минут/часов;
- в конце дня.

Подтверждение перед отметкой
Запрашивать подтверждение:
- при пропуске;
- при удалении записи;
- при завершении курса.

Допустимое отклонение времени приёма
Например:
±15 минут
±30 минут
±1 час

4.9.2.4 Остатки препаратов
Порог предупреждения:
Например:
- осталось на 1 день;
- на 3 дня;
- на неделю.

Автоматическое списание
- включить;
- выключить.

Напоминание о покупке
- за N дней;
- при достижении минимального остатка.

4.9.2.5 Безопасность
Биометрическая защита:
Поддержка:
- Face Unlock;
- отпечаток пальца.
- PIN-код приложения

Автоблокировка
Через:
- сразу;
- 1 минуту;
- 5 минут;
- 15 минут.

4.9.2.6 Данные и память
Очистка истории

Отдельно:
- история уведомлений;
- завершённые курсы;
- временные данные.

Размер локальной базы:
- Отображение занимаемого места.

Очистка кэша

4.9.2.7 Accessibility
Размер шрифта
- маленький;
- средний;
- большой.

Контрастность
Крупные кнопки
Озвучивание уведомлений (опционально)

4.9.3. UX требования к настройкам
Интерфейс
Compose Material 3;

настройки синхронизируются между экранами.

4.9.4. Технические требования
Хранение настроек

Использовать:
DataStore Preferences
или
Proto DataStore.

Требования
- асинхронная работа;
- реактивные обновления через Flow;
- type-safe доступ к настройкам.

4.9.5. Архитектурные требования
Настройки должны:
- быть вынесены в отдельный SettingsRepository;
- иметь единый источник истины;
- поддерживать DI;
- быть доступны через ViewModel.

резервное копирование;

5. Нефункциональные требования:
   Производительность:

- Быстрый запуск (<2 сек)
- Плавный UI
- Минимальное потребление батареи

Надёжность:

- Работа без интернета
- Устойчивость к перезапуску устройства
- Корректное восстановление уведомлений

Безопасность:

- Локальное хранение данных
- Шифрование резервных копий
- Биометрическая защита (опционально)

6. Технические требования
   Платформа:

- Android 8+
- Kotlin
- Jetpack Compose
- MVVM
- Coroutines + Flow

Хранение данных:

- Room Database

DI:
- Hilt/Koin

Навигация:
- Navigation Compose

Асинхронность:
- Kotlin Coroutines

Background tasks:
- WorkManager

7. Архитектура
   Слои:
- UI
- Domain
- Data

Принципы:
- SOLID
- Repository pattern
- Unidirectional Data Flow
- Immutable UI state

8. UX требования:
   Интерфейс должен:
- работать одной рукой;
- иметь крупные элементы;
- минимизировать количество тапов;
- поддерживать тёмную тему;
- быть понятным без обучения.

9. MVP версия

   Обязательно:
- Добавление препаратов
- Расписание
- Напоминания
- Отметка приёма
- История
- Остатки

    Проект считается качественным если:

- код компилируется без ошибок;
- UI стабилен;
- уведомления работают надёжно;
- нет потери данных;
- приложение удобно использовать ежедневно.
